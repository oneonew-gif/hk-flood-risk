## 3. 发布阻塞项与待确认项

### B1 原始数据归档体积（已处理）

- 现象：`hko_api/data/raw/nowcast` 263 MB、全目录 2,837 个文件、合计 276 MB。
- 处理：`.gitignore` 增加 `hko_api/data/raw/`；保留 `hko_api/data/latest/`（约 1.7 MB）供离线演示。
- 发布前确认：`git status` 中不得出现 `hko_api/data/raw/`。

### B2 公开演示快照会显示 STALE（阻塞）

- 现象：公开仓库携带的 `snapshot.js/json` 为某一时刻冻结快照；页面按“获取时间”判定，30 分钟后
  必定显示“过期/失败”，这对首次访问者像故障。
- 建议（任选其一，需用户决定）：
  1. README + 页面顶部注明“演示快照，非实时；实时请本地运行 `hko_fetch.py --loop`”；
  2. 不公开 `data/latest`，改为首次访问提示“请先本地抓取”；
  3. 用 GitHub Actions 定时抓取刷新（涉及仓库写权限与第三方数据再分发，须单独评估）。
- **未自行选择**，等待确认。

### B3 数据授权与再分发（待确认）

- HKO 开放数据可公开引用，但**再分发条款未在仓库中核实**。
- README 已声明来源；发布前需确认是否允许把官方观测快照（`snapshot.json/js`）纳入公开仓库，
  或改为“运行时抓取、不入库”。

### B4 仓库基线（阻塞）

- `git log` 显示当前分支无任何提交；`git status` 全部为 untracked。
- 发布前至少需要：首次提交、`main` 分支基线、LICENSE（当前无）、`.gitignore` 生效验证。
- 本轮未执行提交（用户明确不自动公开）。

### B5 无 CI / 无测试入口（建议）

- 规则测试为 `node hko_api/district/tests/bulletin.test.mjs`，最近结果 **8 passed, 0 failed**。
- 建议加最小 CI（Node 20+ 跑该命令），否则测试记录只能靠手工。

### B6 移动端未实测（待验证）

- 静态检查：有 `viewport`，`@media (max-width:820px)` 切单列；区按钮 2 列、键值 110px+1fr。
- 未做真机或截图验证（浏览器截图工具当前不可用）；370 px 宽度下“數據新鮮度”表格可能横向溢出。
- 建议发布前人工过一遍 375 px 视口，并给表格加横向滚动容器。

### B7 刷新失败在 30 分钟窗口内静默（产品行为，可接受但需知悉）

- 前端每 60 秒拉取快照；若拉取失败，仅 `console.warn`，页面继续显示旧数据；因 `fetch_time` 不变，
  要等超过 30 分钟才出现 STALE 条。
- 影响：短暂断网时用户看到的是“旧但看起来正常”的数据。
- 处置建议：不改变现有服务端 STALE 语义；如需更严格，可增加“连续 2 次拉取失败即提示”，属产品迭代，
  本轮未改。

### B8 无 18 区边界 / 无分区分区预报（产品限制，非阻塞）

- 无官方区界几何 → 只有列表选择器；HKO nowcast 无分区产品 → 不展示分区未来 2 小时数值。
- README 与页面均已说明；不构成发布阻塞，但会被使用者提问，需保留说明。
