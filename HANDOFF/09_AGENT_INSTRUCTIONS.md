## 2. 身份与边界

- 项目**双轨**：研究轨道（论文，冻结优先）+ 产品轨道（可持续开发）
- 你**不是**数据提供方：A 侧（数据）与 B 侧（本仓库，建模）分工；数据口径疑问记录并提请用户向 A 方澄清，**不得自行假设口径**
- 你**不是**项目负责人：训练、调参、标签/划分/阈值变更、覆盖冻结产物、公开发布——一律先获批

## 3. 每条消息开工前的自检

1. 这件事会不会改动冻结产物？→ 是：停止，转独立新目录或请示
2. 这件事是否需要用户批准（清单见 05 §3）？→ 是：先请示再动手
3. 我的表述会不会把「弱监督评分」说成「真实水浸概率」？→ 重写措辞
4. 这是研究任务还是产品任务？→ 报告时分两节写（见 §6）
5. 这项工作是否让系统能力或结论质量真正变好？→ 不能则不做，并向用户说明

## 4. 执行纪律

- **新实验/新数据版本 → 新独立目录**（`outputs/<名>_<YYYYMMDD-HHMMSS>/`、`data/<版本名>/`），禁止原地修改旧目录
- **实验四同**：对照实验必须同数据版本、同样本、同划分、同种子（seed=42）
- **先验证后引用**：未独立验证的实验只能标记「探索性」
- **只读核验优先**：核查类任务不训练、不预测、不改数据；用只读脚本 + 独立输出目录
- **测试基线**：任何代码改动后跑 `python -m pytest`（基线 167 项），回归必须修复或披露
- **迭代记录**：符合迭代定义的改动完成后，主动追加 `ITERATIONS.md`（格式见文件头部约定）；typo/格式/试错不记；数据版本与研究口径变更同时记 `CHANGELOG.md`
- **哈希意识**：引用冻结数据时核对 SHA256（`1749cc00…5cb4e8`）；正式实验产出 manifest 记录哈希与种子

## 5. 表述纪律（写报告/论文/界面文案时）

| 禁止 | 正确表述 |
|---|---|
| 「真实水浸概率」「提前 2 小时预测准确率」 | 「弱监督标签下的相对风险评分（探索性）」 |
| 日期级 0.897 / 格日级 0.950 作为预警能力 | 仅事件日内行级 ROC 0.638 符合 2h 口径；聚合口径注明回顾性 |
| 「社区排名」「黑点街道名」 | 无社区边界映射 → 不生成；网格编号如实标注 grid_id |
| 「SVI 最脆弱社区」 | SVI 方法待验证，不参与排序 |
| 「实时水浸预测」 | 实时功能未实施未批准；Dashboard 仅展示 HKO 官方观测/预报 + 历史评分 |
| 「全期评分」=「测试期评分」 | 必须标注口径；论文实证优先测试期 |

## 7. 用户审批机制

- 请示时给出：目的、改动范围、影响产物、验证方式、回滚方式
- 获批范围**严格受限**：批准 A 实验不意味着可以顺带做 B；完成后**不得自动启动**其他训练
- 用户说「迁移/交接/只读核查」时：不训练、不预测、不改文件（本 HANDOFF 即按此生成）
- 重大分歧或证据不足：明确标注「待验证」，禁止推测填充
