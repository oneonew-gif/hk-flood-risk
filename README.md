# 智慧防洪｜香港城市水浸风险分析与气象信息平台

> 让天气数据更容易理解，让城市水浸风险更容易看见。

**智慧防洪（Smart Flood）** 是一个正在开发的香港城市水浸风险研究与可视化项目。我们把香港天文台的气象资料、历史环境数据、机器学习和地图展示结合起来，希望帮助公众理解雨情，也为城市规划和风险治理提供可以检查、解释的数据依据。

**重要说明：目前平台能展示官方气象观测及历史模型风险评分，但还不能准确预测“未来两小时某地一定会不会水浸”。模型评分不是经过真实水浸事件验证的发生概率，也不能代替香港天文台或政府部门的正式预警。**

## 为什么做这个项目？

同样一场暴雨，低洼地区、排水条件不同的街道，以及临海区域，面临的影响可能很不一样。单看全港雨量或暴雨警告，不容易理解风险在哪里、为什么会不同。

我们想回答三个问题：

- **现在天气怎么样？** 用更直观的方式阅读香港天文台的降雨观测和警告。
- **哪些地方在历史数据下更值得关注？** 在地图上展示模型的相对风险评分，而不是只看一串数字。
- **这些评分从何而来、是否可靠？** 用模型对照、变量解释和数据审计，公开呈现模型的能力与不足。

### 1. 查看香港 18 区气象播报

在项目文件夹中运行：

```bash
# 获取香港天文台最新数据（需要网络连接）
python3 hko_api/hko_fetch.py --once

# 在项目根目录启动本地网页服务
python3 -m http.server 8000
```

然后在浏览器打开：**http://localhost:8000/hko_api/district/**

你可以选择香港 18 个区之一，查看过去一小时的分区降雨观测和全港警告。页面也会显示数据的新鲜程度；如果接口异常或数据过期，会明确提示，而不是编造新数据。

这里的“微量、小雨、中雨”等文字档位，是项目为了便于阅读设置的**展示规则，并非香港天文台官方雨量分级**。分区雨量取官方分区观测数据中的最大值，并不代表区内每个位置都下了相同的雨。

### 2. 查看历史评分地图

在本地服务启动后，还可以打开：**http://localhost:8000/hko_api/dashboard.html**

地图展示 **5,517 个 500 米网格**的历史模型评分。可以对比不同的历史统计口径、查看网格详情，并单独查看气象观测或官方预报信息。

**注意：** 地图上的历史评分并不是当前实时水浸概率；网格中心点也不是实际水浸边界。如果网页使用已保存的数据快照，必须看清其更新时间。

## 它是怎么工作的？

可以把整个系统理解为三层：

1. **收集信息。** 整理香港天文台的公开气象数据，以及研究所需的历史降雨、地形和空间资料。
2. **研究风险。** 使用 XGBoost 等机器学习方法，学习历史数据里与水浸相关的模式；再与更简单的模型比较，并检查是否存在数据错误或结果虚高。
3. **用地图解释结果。** 把模型评分关联到香港网格，结合 SHAP 等解释方法，帮助读者理解模型主要参考哪些因素。

这里的几个技术名词可以简单理解为：**XGBoost** 是一种从数据中学习规律的方法；**GIS** 是把信息放到地图上进行空间分析的工具；**SHAP** 用来帮助解释模型为什么给出某种评分。

## 目前的研究发现

项目已经使用修复后的历史数据完成一轮正式模型实验。研究覆盖 **2018 年至 2026 年 9 月**的数据，按照年份划分训练、验证和测试阶段，其中最终测试阶段为 **2023 年 1 月至 2026 年 9 月**。

一个重要的数据质量发现是：早期数据曾错误地把部分“红色火灾危险警告”当成“红色暴雨警告”。我们据香港天文台官方警告记录修复了标签，并保存了修复前后的资料及核验记录。**这也说明：模型跑出高分，不代表原始数据一定正确。**

在修复后的数据上：

- 主要 XGBoost 模型在测试集上的 **ROC-AUC 约为 0.751**，**PR-AUC 约为 0.184**；一个逻辑回归对照模型的 PR-AUC 约为 **0.291**。这些是对当前*弱监督标签*的评价，不是对真实水浸概率的验证。
- 模型对**地形等静态差异**有一定识别能力，但在暴雨事件内部、不同时间点和网格之间区分风险的表现仍然有限。
- 日期级或按日聚合后看起来较高的指标，包含事后信息，**不能当成提前两小时预警的证据**。
- 潮位与降雨可能存在值得继续研究的关联，但现有模型**尚未证明具备可靠的雨潮复合预警能力**。

这些不足不被隐藏。项目的目标不仅是开发页面，更是逐步建立一个**能解释、有证据、知道自身边界**的模型体系。

## 项目结构

```text
hk-flood-risk/
├── hko_api/                # 气象数据获取、18 区播报与地图展示
│   ├── district/           # 18 区气象播报页面
│   └── dashboard.html      # 气象信息与历史风险评分 Dashboard
├── src/floodrisk/         # 机器学习、数据检查、预测与 GIS 相关代码
├── configs/               # 模型与流程设置
├── scripts/               # 数据审计、实验与结果整理脚本
├── tests/                 # 自动化测试
├── reports/               # 研究报告与质量核验
├── HANDOFF/               # 项目结构与交接说明
├── PROJECT_PRINCIPLES.md  # 长期研发规范
├── ITERATIONS.md          # 项目迭代记录
└── CHANGELOG.md           # 主要变更记录
```

研究数据、模型文件和大型实验输出可能因大小、授权或隐私原因**不随公开代码发布**。因此，仅下载代码未必能够复现论文中的全部实验数值；需要相应的数据版本及许可。仓库中的合成数据仅用于测试程序，不能作为香港实际水浸证据。

## 开发者如何开始？

建议使用 **Python 3.10 或以上**。从项目根目录安装依赖并测试：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
python -m pytest
```

Windows 用户需要使用对应的虚拟环境激活命令。macOS 如果提示 XGBoost 缺少 `libomp`，可根据自己的系统环境安装 OpenMP 运行库。

18 区播报的规则测试：

```bash
node hko_api/district/tests/bulletin.test.mjs
```

具体建模操作、参数与实验复现路径，请参考 `HANDOFF/`、`reports/` 和 `configs/`。请勿直接覆盖已冻结的研究数据和模型结果。

## 项目接下来会做什么？

我们会优先完善数据质量和空间验证，包括检验模型在未见过的地区是否仍可靠；核对统计区域人口数据与脆弱性指标；确认实时天气数据与训练阶段变量是否一致，然后才考虑独立开发动态推理能力。**新增实验和正式模型替换均需单独审核，不会直接改写已有论文结果。**

## 数据来源与使用声明

本项目使用或研究过香港天文台公开数据、NASA POWER、ERA5、GIS 地形资料及香港人口统计相关资料。不同数据的时间范围、空间精度与许可条件可能不同；引用与再分发需遵守各来源的规定，不能因为“开放可读取”就默认“允许随仓库重新发布”。

**目前本项目属于研究及原型阶段，不是香港政府官方防洪服务，也不提供疏散、救援或个人安全决策指令。遇到恶劣天气请以香港天文台及有关部门发布的正式信息为准。**
